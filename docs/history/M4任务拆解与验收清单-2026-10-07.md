## 5. 测试集先行（WP1 的详细设计）

### 5.1 改写矩阵（**最重要**：数据损坏风险）

对每种**链接形式** × 每种**上下文**给定期望输出：

| 链接形式 | 应被改写 |
| --- | --- |
| `[[A]]` | ✅ → `[[B]]` |
| `[[A\|别名]]` | ✅ → `[[B\|别名]]`（别名原样保留） |
| `[[folder/A#标题]]` | ✅ → `[[folder/B#标题]]`（锚点原样保留） |
| `[[A#^bid]]` | ✅ → `[[B#^bid]]` |
| `![[A]]` / `![[A#标题]]`（嵌入） | ✅ → `![[B]]` / `![[B#标题]]` |
| `[文本](A.md)`（markdown 内联） | ✅ → `[文本](B.md)` |
| `[文本](A.md "标题")` | ✅ → `[文本](B.md "标题")` |

| 上下文 | 必须**不动** |
| --- | --- |
| 围栏代码块 ``` 内 | ❌ 不改（**AC-FILE-01 的硬要求：2 处保持 A**） |
| 行内代码 `` `[[A]]` `` | ❌ 不改 |
| frontmatter 的 `aliases:` 等 | ❌ 不改（**但目标文件的 frontmatter 别名参与匹配**，见 FR-LINK-02 ③） |
| HTML 注释 `<!-- [[A]] -->` | ❌ 不改 |
| 已指向别处的链接（`[[C]]`） | ❌ 不改 |
| 大小写不同的引用（`[[a]]` 指向 `A.md`） | ✅ 改（FR-LINK-02 ② 大小写不敏感匹配） |

### 5.2 反链夹具（对齐 AC-LINK-01/11/14/15）

- 50 篇引用 `B.md`（三种形式 + 锚点 + 嵌入）→ 期望：50 条、与 `SELECT COUNT(*) ... dst_file_id=<B> AND status='resolved'` **一致**；
- 每条含**正确的上下文片段**（前 2 行 + 本行 + 后 2 行，行号 1-based）、链接**高亮区间**（字节偏移）；
- 分组：普通 vs `embed` 分开计数；按来源分组；
- 边界：文件首行/末行的链接（片段不足 N 行）、同一行两处链接、超长行截断。

### 5.3 悬空/歧义/孤立夹具（对齐 AC-LINK-04/05/21/22）

- 悬空：同一目标名被多篇引用 → 按目标名分组 + 引用次数；创建目标后状态变 resolved（AC-LINK-02）；
- 歧义：`folder1/note.md` + `folder2/note.md` + 10 处 `[[note]]` → 10 条 ambiguous、2 候选（AC-LINK-04）；
- 孤立：无出链且无入链；**自链接不计入**（FR-LINK-07/21）；
- 锚点失效：`[[B#某标题]]` → 删标题后仍 resolved + `anchor_missing`（AC-LINK-05）。

### 5.4 原子性与回滚夹具（对齐 AC-FILE-02）

- 50 个文件、第 30 个写失败（用一个可注入的写失败钩子，或把第 30 个文件的父目录设为只读）→ 断言前 29 个**逐字节**等于备份、重命名为原状、失败报告含路径与原因；
- 重命名失败 → 断言**零改写**；改写失败 → 断言重命名被撤销；
- 反例（**必须不存在**）：链接已指向新名而文件仍旧名。

### 5.5 清点测试（反"分母自证"）

从 **PRD 原文**抽取：`FR-LINK-\d+`、`FR-FILE-2[12]`、`AC-LINK-0[1-5]`、`AC-FILE-0[12]`、`NFR-PERF-16`，断言**每一条**都出现在本文件的覆盖表里，且覆盖表里的每条都真实存在（**双向**，不重不漏）。
注：**FR-LINK-19 不存在**（已核实：FR-LINK 共 20 条，编号为 01~07、10~18、20~23），清点测试按真实编号建，不得假设连号。

### 9.2 新增裁定：**重命名 + 改写的入口**（重要）

PRD §5.3.3 明确 `file_rename`「重命名（**不含**链接改写）」。因此"改名并更新链接"的**唯一**正确流程是：

```
link_rewrite_preview { fromRef, toRef, rename: { from, to } }   ← 只读，冻结改名规格
        ↓ 用户确认（"将修改 N 个文件中的 M 处"）
link_rewrite_apply { previewId, rename: { from, to } }          ← 同一次可回滚操作（FR-FILE-22）
```

**前端不得再调用 `file_rename`**（否则会重命名两次）；`file_rename` 保留给"纯改名不改链接"。
