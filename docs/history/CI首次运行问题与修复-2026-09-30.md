# CI 首次运行问题与修复（2026-09-30）

> 本文件是**操作记录**，不是真相源。规则已固化到技术方案 §3.6.1 与 §11.4。

## 1. 现象

首次推送 `main`（`4ac711f`）后，GitHub Actions 的 **CI #1** 与 **Platform Smoke #1** 在 Rust 步骤全部失败，三平台报同一错误：

```
error: rustc 1.88.0 is not supported by the following packages:
  muda@0.20.0 requires rustc 1.90
  tauri@2.12.0 requires rustc 1.90
  tauri-build@2.7.0 requires rustc 1.90
  tauri-codegen@2.7.0 / tauri-macros@2.7.0 / tauri-plugin@2.7.0 requires rustc 1.90
  tauri-runtime@2.12.0 / tauri-runtime-wry@2.12.0 requires rustc 1.90
  tauri-utils@2.10.0 requires rustc 1.90
  tauri-plugin-dialog/shell/opener/process 各新版本 requires rustc 1.90
```

## 2. 根因

`Cargo.lock` 中的 **Tauri 家族被解析到了 2.12.0 一代**（要求 rustc 1.90），而全仓固定 **rustc 1.88**。

- 该漂移**在初始提交时就已存在**（`git show 0b43dd5:Cargo.lock` 即 2.12.0），不是后续改动引入的；
- **本地构建不报错**，因为本机 toolchain 是 1.98.1（高于依赖要求），MSRV 校验只在 toolchain **低于**依赖 `rust-version` 时才触发——所以这个问题**只有 CI 能发现**；
- 深层原因：工作区使用 `resolver = "2"` 且**没有** MSRV 感知配置，cargo 按「最新可用」解析；`rust-version = "1.88"` 虽已声明，但未被解析器采纳。

## 3. 修复

| # | 动作 | 说明 |
| --- | --- | --- |
| 1 | 新增 `.cargo/config.toml`：`[resolver] incompatible-rust-versions = "fallback"` | 启用 Cargo 1.84+ 的 **MSRV 感知解析** |
| 2 | 工作区 `Cargo.toml`：`resolver = "2"` → `"3"` | 让 MSRV 感知成为默认行为 |
| 3 | 删除 `Cargo.lock` 并 `cargo generate-lockfile` | 让解析器在 MSRV 约束下重新选版本 |
| 4 | `package.json` / `scripts/run-gates.mjs` / `ci.yml` / `platform-smoke.yml` 的 cargo 命令统一加 `--locked` | 防止 manifest 变动时锁被静默重解析（Rust 版 R-17） |
| 5 | 修正 `ci.yml` 中过时的 job 名「16 项门禁」→「17 项门禁」 | 与 PRD §8.4 的 17 项对齐 |

## 4. 验证

- `cargo +1.88.0 check --workspace --all-targets --locked`（使用与 CI 相同的 1.88 工具链，本机已安装）
- 重新推送后 GitHub Actions 结果见提交对应的运行记录

## 5. 经验

1. **本地 toolchain 高于 MSRV 时，MSRV 违规不会暴露**——必须靠 CI 或本地主动用 `rustup run 1.88.0` 验证；
2. **`rust-version` 声明 ≠ MSRV 感知解析**，后者需要 resolver 配置；
3. 依赖「声明层面兼容 + 锁定层面精确」的策略在 Rust 侧必须**同时**有 `--locked` 与 MSRV 感知解析，否则锁会在 manifest 变动时静默漂移。
