数据所有权与真相源

  • Markdown 文件是唯一真相源：正文、wikilink、标签、frontmatter、Block ID 全部可从 .md 完整还原
  • index.db 是纯派生数据：删除后重新打开 Vault 即可 100% 重建（成功判据 SJ-03）
  • 索引签名 = schema 版本 + 解析器版本 + 分词器版本&词典哈希 + Vault 绝对路径，任一变化即全量重建
  • global.db 存软件配置（Vault 注册表、偏好、窗口状态），丢失不影响任何笔记数据
  • 禁止在索引库存储无法从 Markdown 重建的数据（架构约束 AC-06）
  • 用户可用任意编辑器直接改文件、可纳入 Git；.knowlpad/ 建议加入 .gitignore（不自动修改）

关键数据流

  • 冷启动：Vault 校验 → 签名比对 → walkdir 遍历 → 线程池并行解析+分词 → mpsc → 单写线程批量事务 → 全局链接裁决
  • 解析与写库分离：解析 CPU 密集可并行，写库 IO 密集须串行，规避 SQLite 写锁竞争
  • 编辑保存：防抖 1s → base_mtime 冲突检测 → 原子写入（临时文件 + fsync + rename + 父目录 fsync）→ 增量索引
  • 重命名改写：预览（只读，冻结 span）→ 用户确认 → 备份 → 事务内原子改写 → 失败全量回滚
  • 外部变更：notify 监听 → 200ms 去抖动归并 → 索引队列 → 事件推送前端局部失效
  • 中文搜索：jieba 预分词写入 FTS5（unicode61 不分中文），查询同样先分词再构造 MATCH

最高风险模块与红线

  • rewrite 批量链接改写：唯一会批量修改用户既有文件的操作。必须「备份 + 预览 + 全有或全无 + 回滚」，任一环节缺失即视为缺陷
  • 陈旧检测（防 TOCTOU）：预览与执行之间文件可能被外部修改，导致 span 偏移错位损坏无关内容 —— 双重校验（mtime 整体 + 逐 span 内容）
  • path_guard：词法 .. 拦截与符号链接 canonical 二次校验互补，缺一即可被绕过
  • note_io 原子写入：任何时刻强杀或断电，磁盘上必须是完整旧内容或完整新内容，绝不允许半截文件
  • watcher 死循环防护：.knowlpad/ 在 Vault 内，不过滤则索引写入触发监听形成无限循环
  • 16 条红线见 PRD §8.2；23 种错误码统一收敛为 AppError，禁止向前端抛未分类字符串

范围边界与性能目标

  • V1.0 交付 12 个模块：Vault · 文件树 · 编辑器 · 双链 · 搜索 · 图谱 · 标签 · 附件 · 命令面板 · 回收站 · 设置 · 更新
  • 明确排除 15 项：插件系统、云同步、移动端、协同编辑、AI、加密 Vault、遥测等（PRD §1.4 Out of Scope）
  • 性能：冷启动 <1.5s · 万篇搜索 <200ms · 输入延迟 <16ms · 10 万节点 ≥50 FPS · 空闲 CPU <1%
  • 规模基准：标准库 3000 篇 / 大库 20000 篇 / 压力库 100000 篇
  • 跨平台：Windows 10 21H2+ · macOS 12+（Intel & Apple Silicon）· Linux（deb + AppImage）
  • 11 个里程碑 M0→M10，关键路径为数据层与链接模块；M3 解析器与 M4 链接改写为最高技术风险环节
