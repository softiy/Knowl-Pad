# PR 流程工具（2026-10-01）

> 本文件是**工具说明与设计记录**，不是真相源。规则来源：PRD CODE-09、AGENTS.md §9.6。

## 1. 为什么需要它

分支保护启用后，每次改动都要走「新建分支 → 推送 → 开 PR → 等两项必需检查 → 合并 → 同步 main」。
手工执行有两个已真实发生的问题：

1. **断网中断无法续跑** —— 2026-10-01 凌晨断网，导致「等检查 → 合并」这一步失败，且状态需要人工重新确认；
2. **状态易错** —— PR 号、head SHA、检查结论要手动在多个调用之间传递，容易误判（当晚就出现过把检查状态读成空值的情况）。

## 2. 命令与选项

```bash
pnpm pr                    # run（默认）：推送 → 开 PR → 等必需检查 → 合并 → 同步 main → 校验 Gitee 镜像
pnpm pr -- open            # 只推送并创建/复用 PR
pnpm pr -- status          # 打印当前 PR 与必需检查状态
pnpm pr -- merge           # 等待检查全绿后合并
pnpm pr -- sync            # 切回 main 并快进
```

选项：`--title`、`--body-file`、`--base`、`--wait <分钟>`（默认 20，0=不等待）、`--interval <秒>`、
`--retries <次数>`、`--no-merge`、`--no-mirror`、`--repo owner/name`。

## 3. 设计要点

| 要点 | 实现 |
| --- | --- |
| **令牌不落地** | 通过 `git credential fill` 向系统凭据管理器索取，只在内存使用；**不打印、不写文件**（脚本内也不存在读取环境变量令牌的分支，避免误用明文） |
| **可续跑** | 状态写入 `.git/pr-flow-state.json`（branch / pr / headSha / base）；重跑时先复用已存在的 PR，**不会重复创建** |
| **断网容错** | 所有 API 调用带指数退避重试（1.5s→3s→6s…封顶 20s，默认 5 次）；轮询期间连续失败只提示不退出；超时后给出明确的手工补救命令 |
| **合并门槛与分支保护一致** | 必需检查（`17 项门禁（与本地同一脚本）`、`Windows 冒烟（构建 + 单元测试）`）全部 `success/skipped/neutral` 才合并；额外检查（三平台冒烟）只作 `unknown` 报告，不影响结论——与分支保护的必需检查集合保持一致 |
| **不绕过保护** | 工具走 `PUT /pulls/{n}/merge`（合并 PR），不做任何直推；分支保护仍是最终防线 |
| **拒绝在 main 上运行** | 在 `main`/`master` 上直接报错，提示先建分支（PRD CODE-09） |
| **合并后自动校验镜像** | 合并后轮询 Gitee 匿名 API（最多 5 分钟），确认镜像已同步（实测 13–21 秒） |

## 4. 测试

`tests/unit/pr-flow.spec.mjs`，14 项，覆盖 `evaluateChecks` / `backoffMs` / `parseRepoFromUrl` / `parseArgs`。

> **测试抓到一个真 bug**：当必需检查**尚未出现**在 check-runs 列表里时（刚开 PR 的头几秒），
> `evaluateChecks` 会对 `undefined` 取 `.status` 而抛异常。已修复为先把"缺失"与"在列"分开处理。
> 这正是"测试跟着改"（AGENTS.md §9.4）的价值。

## 5. 已知限制

1. 仅支持 GitHub REST API（要求 `api.github.com` 可达；Gitee 镜像校验为匿名查询，私有仓库需另行处理）；
2. 合并方式**固定为 rebase**（保留原始提交信息、历史线性），暂不支持 squash/merge commit；
3. 必需检查的名称硬编码在脚本内，**必须与 `ci.yml` 的 job 名和分支保护的必需检查列表三者一致**——改 job 名时需同步三处（建议在 PR 描述里说明）。
