### 2.3 保护分支（评审模式，已实测 ✅）

配置：`管理 → 保护分支设置` 新建规则，`main`，并对 `main` 启用了**评审模式**（无权限推送 → 自动转 PR）。

实测（构造一个空提交后尝试直推 `main`）：

```
remote: Cannot push to a protected branch 'refs/heads/main' directly
remote: Gitee created a Pull Request for code review (refs/heads/auto/main/10140540/... -> refs/heads/main)
remote: Please visit the URL: https://gitee.com/klincode/knowl-pad/pulls/1
```

**结论**：推送被拒，`main` 未被改动（仍为 `250c1ab`），测试提交被自动转成 PR —— 与 GitHub 的 `enforce_admins` 效果等价，且更友好（不报错，直接给 PR 入口）。
测试残留已清理：关闭该 PR（`PATCH /pulls/1 {state:closed}`）、删除自动分支（Gitee API 的 `DELETE /branches` 返回 **405 不支持**，改用 `git push gitee --delete`）。

### 2.4 保护标签设置 —— **企业版功能，个人仓库不可用**

Gitee 侧无法保护 `v*` 标签。**已在 GitHub 侧补上等价能力**（GitHub 的 `/tags/protection` 端点已下线，改用 **repository ruleset**）：

| 项 | 值 |
| --- | --- |
| ruleset id / name | `24267681` / `protect-release-tags` |
| target | `tag` |
| 生效范围 | `refs/tags/v*` |
| 规则 | `deletion`（禁止删除）+ `update`（禁止移动/覆盖） |
| enforcement | `active` |

> 由于标签由镜像同步到 Gitee，即使 Gitee 侧标签被删，下一次镜像同步也会恢复；真正的保护点在 GitHub（唯一真相源）。

### 2.5 推送规则设置（建议全部保持不勾）

该页提供：推送邮箱限制（只能推送自己的提交 / 指定邮箱域名）、**提交信息正则校验**、单文件大小限制、以及「仓库管理员不受上述规则限制」。

**建议全部不勾**，理由：Gitee 是**只读镜像通道**，提交均由 GitHub 同步而来；而这类规则存在**拦截镜像同步**的风险（连续 5 次失败会导致镜像被强制停止），且对已受 GitHub 保护 + CI 的流程没有增量价值。
若将来仍要开启，提交信息正则可用：`^(feat|fix|docs|style|refactor|perf|test|build|ci|chore|revert)(\([a-z0-9._-]+\))?!?: .+`，但需先验证它是否拦截镜像同步。

### 2.6 定位说明

Gitee 是**分发与镜像**渠道（Release 与 updater 源），开发与 CI 以 GitHub 为准。两侧现在都禁止直推 `main`：
GitHub 硬拒绝（`GH006`），Gitee 评审模式（自动转 PR）。

## 3. 标准开发流程

```bash
git switch -c feat/<简短描述>     # 分支前缀：feat/ fix/ chore/ docs/ refactor/
# 改动 + 本地 pnpm ci 全绿
git commit -m "feat(scope): 说明"  # Conventional Commits（PRD CODE-09）
git push -u origin HEAD           # 推分支（推 main 会被拒绝）
# 在 GitHub 开 PR（自动带 .github/pull_request_template.md 的清单）
# CI 全绿 → 合并 → 删除分支
```

## 5. 紧急处置（如需绕过保护）

仅在 CI 自身故障、必须推送修复时使用，用完立刻恢复：

1. **推荐**：网页临时把 `enforce_admins` 或必需检查关掉 → 推送修复 → **立即恢复**；
2. 或经 API：`DELETE /repos/softiy/Knowl-Pad/branches/main/protection`（会清空全部设置，不推荐——恢复成本高）。

> 注意：`enforce_admins` 开启后，**管理员也无法直推**；若忘记恢复流程，日常改动一律走 PR 即可。
