## 3. 工作包拆解（按依赖排序）

### WP1 全局库与连接层（`global.db`）
- **目标**：建立 `DbPool`（单写连接 + 读连接池）与 `global.db` 的建库、PRAGMA、迁移骨架。
- **权威出处**：技术方案 §4.1（连接管理）、§4.2（PRAGMA）、§4.3（事务模式）、§4.5（全局库版本化迁移）；PRD §3.2.2（DDL：`meta`/`vault`/`preference`/`vault_state`）、MIG-02/MIG-03/MIG-05。
- **交付**：`storage` 模块（连接池 + PRAGMA 应用 + `schema_version` 迁移执行器）；`vault` 注册表的读写 API。
- **验收**：MIG-05 的迁移测试（构造旧版本库 → 迁移 → 断言结构与数据）；将来版本更高时**拒绝写入**（MIG-03）。
- **注意**：`foreign_keys = ON` 必须显式开启（§4.2 明确 rusqlite 默认关闭）。

### WP2 索引库 schema 与迁移（`index.db`）
- **目标**：`<Vault>/.knowlpad/index.db` 的 DDL 落地与**丢弃重建**策略（MIG-01）。
- **权威出处**：PRD §3.2/§3.3（DDL：`file`/`heading`/`block_id`/`link`/`tag`/`file_tag`/`file_alias` + FTS5 虚拟表）、§3.6（MIG-01）；技术方案 §4.4。
- **交付**：完整 DDL + `schema_version` 比对 → 不一致即重建（先删库文件再建，不做在线 ALTER）。
- **验收**：DDL 与索引签名版本号一致性测试；建库后 `PRAGMA foreign_keys` 生效验证（级联删除正确）。
- **注意**：M1 只建结构，**不实现解析与写入**（解析器属 M3）——但要有最小写入路径以便测试级联与事务。

### WP3 Vault 生命周期
- **目标**：`vault_open` / `vault_create` / `vault_close` / `vault_list` 从 stub 变为真实实现；Vault 切换与状态持久化。
- **权威出处**：PRD §4.1（FR-VAULT-01~12）、§5.3（命令签名）、§3.7（`.knowlpad/` 结构、FR-STORAGE-01~04）。
- **交付**：`.knowlpad/` 自动创建（权限仅当前用户）；打开时恢复上次 Vault；切换时刷盘 + 关闭连接；列表移除**不删文件**。
- **验收**：AC-VAULT-02（路径失效不崩溃不建目录）、AC-VAULT-03（切换数据完整性 < 2s）、AC-VAULT-04（移除不删文件）。

### WP4 路径安全全量落地（SEC-02）
- **目标**：把领域层已有的校验接入**每一个**接收路径参数的 Command，并补齐穿越/符号链接测试集。
- **权威出处**：PRD SEC-02、T-03/T-04、IPC-04、RT-02、FR-VAULT-10。
- **交付**：统一入口（命令层不再各自处理路径）；`E_PATH_OUTSIDE_VAULT` 返回与日志；**拒绝 `\0`**、拒绝绝对路径（除注册接口）。
- **验收**：路径穿越测试集**全拦截**（M1 DoD 原文）；符号链接逃逸用例。
- **注意**：前端校验（RT-02）不作为安全边界，Rust 侧必须独立校验。

### WP5 原子写入协议强化 + 崩溃一致性
- **目标**：把 §6.3 协议补全到可验证状态，重点解决 **RISK-09（Windows rename 语义）**。
- **权威出处**：技术方案 §6.3；PRD AC-REL-01、NFR-REL-01/02、RISK-09。
- **交付**：平台分支的 `replace()`；`.kp-tmp-*` 启动清理（仅 `.knowlpad/` 内允许残留）；单文件保存的 `base_mtime` 冲突路径。
- **验收**：**AC-REL-01**（100 文件 × 1000 次随机强杀 → 全部「完整旧内容或完整新内容」、无零字节、无残留）。

### WP6 IPC 契约与前端最小接入
- **目标**：命令签名/错误码/事件与前端封装对齐，保证门禁 17 与 `ErrorCode` 映射持续通过。
- **权威出处**：PRD §5.2（错误码）、§5.3（命令）、IPC 系列；技术方案 §8。
- **交付**：`src/core/ipc/commands.ts` 与 Rust 命令一一对应；`IndexStatus`/`VaultInfo` 类型同步。
- **验收**：门禁 17 通过；前端最小冒烟（打开 Vault → 状态栏显示名称，FR-VAULT-11 属 P1，可后置）。

## 5. ✅ M1 DoD 口径（已于 2026-10-01 确认并写回 PRD）

| 验收标准 | 为什么在 M1 无法满足 | 建议口径 |
| --- | --- | --- |
| **AC-VAULT-01**（300 篇笔记：索引完成、链接与标签解析符合 §3.1） | 依赖 Markdown 解析器（**M3**）与链接裁决（**M4**）；M1 尚无解析能力 | M1 只验证其中**与存储相关**的部分：不修改第三方配置目录（逐字节比对）、`.knowlpad/` 正确创建、文件计数正确；解析断言**移到 M3** |
| **AC-VAULT-05**（20000 文件首次索引、进度可取消、UI 不冻结） | 依赖索引引擎（**M3**）与文件树 UI（**M2**） | 整条**移到 M3** |

**确认结果（2026-10-01）**：按上述建议执行。已写回真相源：

- **PRD §9.1** 的 M1 DoD 已改为可验证口径（AC-VAULT-02/03/04 全通过 + AC-VAULT-01 存储相关部分）；
- **PRD 勘误表新增 D-08** 记录该口径调整及依据；
- 本文档 §4 验收清单按新口径执行（原 11 项不变，解析类断言不在其中）。
