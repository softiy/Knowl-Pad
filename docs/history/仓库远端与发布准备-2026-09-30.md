## 2. GitHub 网络阻断（本机环境事实）

| 目标 | 结果 |
| --- | --- |
| `https://api.github.com` | ✅ 3/3 成功 |
| `https://github.com` | ⛔ 0/3（20s 连接超时） |
| `https://codeload.github.com` | ⛔ 0/3 |
| DNS 解析 | `github.com → 20.205.243.166`、`api.github.com → 20.205.243.168`（解析正常，属**连接被阻断**而非 DNS 故障） |
| 代理配置 | WinHTTP「Direct access」、`ProxyEnable=0`、无 `HTTP(S)_PROXY` |
| `git push --dry-run origin main` | `Failed to connect to github.com:443 after 21055 ms` |

**结论**：本机无法向 GitHub 推送，因此**第 ③ 步（在 GitHub Actions 取得 17/17 runner 证据）暂时阻塞**。可选解法：

1. 在可访问 github.com 的网络/主机上执行：`git push -u origin main`（远端已配置好）；
2. 若本机有可用代理，配置后即可推送：`git config --global http.https://github.com.proxy http://127.0.0.1:<port>`；
3. 若长期无法访问 GitHub，则按 `docs/history/CI替代方案.md` §6 回退到 Gitee Go（需重写流水线，生态较弱）。

> `gh` CLI 本机未安装；`git` 使用 Windows 凭据管理器（`credential.helper=manager`），Gitee 凭据可用，GitHub 凭据未验证（因网络不可达）。

## 3. ⚠️ 私有仓库对自动更新（updater）的影响（必须决策）

当前 **GitHub 与 Gitee 两个仓库都是私有的**。这会影响 PRD FR-UPDATE 系列的端到端可用性：

- **私有仓库的 Release 资产需要认证才能下载**。客户端 updater 是**匿名**请求（`tauri.conf.json` 的 `endpoints` 只带 URL，不带 token），因此：
  - `latest.json` 会返回 401/404；
  - 即使拿到清单，`.msi`/`.deb`/`.AppImage`/`.dmg` 的下载同样会被拒绝。
- 且**不应**把访问令牌内置进客户端（可被提取，且违反最小权限原则）。

**可选方案**（择一，建议 M9 前定）：

| 方案 | 说明 |
| --- | --- |
| A. 分发仓库公开 | 开发仓库可保持私有，但把 **Release 所在仓库**在发布阶段设为公开（或另建公开的 `knowl-pad-releases` 仓库专门托管资产） |
| B. 自建公开静态端点 | 用对象存储/CDN 托管 `latest.json` 与安装包（需新增运维面，且 PRD 要求除更新检查外离线可用——更新检查本就允许联网） |
| C. 暂不启用自动更新 | V1.0 先只提供手动下载安装，把自动更新推迟到有公开分发端点的版本（需同步修改 PRD FR-UPDATE 范围与 X 系列排除项） |

> 该约束在 M0 不影响开发与门禁；但**必须在 M9（自动更新）之前解决**，否则 updater 无法端到端验收。
