## 8. 本轮过程教训

1. **搜索缓存会过期**：批量改写文档后，用 grep 复核「还有没有旧表述」得到了**过期的行号与内容**，导致我两次基于错误前提去"修"已经不存在的文本，白跑两轮。正确做法：**写入后用 read 直接读文件**，或重新扫描文件内容本身，而不是依赖可能过期的索引。
2. **表格类文档要有结构校验**：本轮两次把新行写成了 5 列（表头是 4 列），且文本里混入裸 `|` 破坏表格。已加归一化脚本（按 id 行重排为 4 列，把文本内 `|` 转全角）并校验「列数分布唯一」。
3. **"顺延"必须写到接收方**：M1 把 Vault UI 顺延给 M2，但只写在**源**里程碑的报告里，接收方的计划里没有 → 交接处蒸发（本轮 blocker 的根因）。落地要求：顺延项必须**同时**写进接收里程碑的计划（或 DEBT）。
4. **规划完备性要机器可查**：5 个 P0 域无归属，靠人读里程碑表发现不了。已新增 **PRD §9.1.1 需求域 → 里程碑覆盖表**，可用脚本检查"每个域至少出现在一个里程碑归属里"。
